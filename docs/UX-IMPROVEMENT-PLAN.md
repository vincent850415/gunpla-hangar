# 格納庫使用者體驗改善方案與 Session 交接

建立日期：2026-11-10。基準版本：package.json 0.3.1。

本文件是待實作規格，不代表功能已完成。依 README、main.jsx、style.css、storage.js、export.mjs 與現有 UI 測試靜態檢視整理，尚未進行使用者訪談或本輪瀏覽器驗證。接手時先檢查 git status 與最新程式，保留其他人的修改。

## 1. 目標與邊界

降低批次建檔的點擊次數、避免編輯成果遺失、提升查找位置與備份還原的可靠性。

- 保留繁體中文、現有綠色視覺風格、本機優先與離線辨識。
- 照片不傳雲端；不新增帳號、雲端同步、付費服務或完整商品資料庫。
- Excel 維持四欄：比例、商品名稱（含規格）、價格、存放位置；依作品系列分頁，只輸出已確認且未刪除的商品。
- 不藉本次改動重寫 OCR 演算法。OCR 結果仍需人工確認。
- 價格空白與數值 0 必須分開保存，既有 HGUC 等商品線規則必須保留。
- 本文件包含完整改善範圍；分階段交付，每階段明確記錄已完成與未完成項目。估工須由接手者檢視後提出，本文件不承諾工時。

## 4. 功能規格與逐項驗收

### UX-01／P1：連續確認模式

- 待確認清單增加「開始確認」，以當下篩選／排序後、未刪除且非 processing 的待確認紀錄建立 ID 佇列快照。
- Editor 顯示「第 n／共 m 筆」，提供上一筆、下一筆及「確認並開啟下一筆」。一般編輯保留「確認並儲存」。
- 儲存成功後再前進；最後一筆顯示完成摘要並回到清單。已刪除／不存在的 ID 自動略過，確認成功不因篩選清單縮減而跳號或漏筆。
- 上下筆不隱含確認；遇到未儲存內容套用 UX-02。驗證失敗留在原筆並聚焦問題欄位。
- 儲存失敗保留草稿，顯示重試與備份入口，不顯示完成或自動前進。
- 驗收：建立 3 筆待確認與 1 筆已確認，確認佇列只包含 3 筆；依序確認、跳過、返回修改皆不漏筆；最後摘要正確。加入儲存失敗情境驗證。

### UX-02／P1：草稿保護與安全重新辨識

- 比較編輯初始值與目前欄位值以判斷 dirty，不以新物件參照判斷。儲存成功後重設基準。
- 關閉按鈕、Escape、切換上下筆皆使用同一離開檢查。dirty 時提供「繼續編輯」「捨棄修改」「儲存為待確認後離開」；驗證或儲存失敗不得離開。
- 瀏覽器關閉／重新整理在有未存草稿或未完成持久化時註冊 beforeunload，其他時候移除；瀏覽器原生提示不能保證出現，不宣稱能完全防止關頁遺失。
- 重新辨識結果先存為暫存候選，不直接修改已保存紀錄。保留現有草稿、價格、位置與既有確認狀態直到使用者套用。
- 比較商品名稱、系列／商品線、規格、比例；預設保留目前值，提供逐欄採用新值及全部採用。商品線與系列需作為相容的一組處理。
- 套用只更新草稿；採用辨識欄位後須重新人工確認。放棄、失敗或中斷候選辨識不損害原資料。採用時同步處理 evidence、warnings、ocrEngine，避免新舊證據混用。
- 驗收：修改價格後按 Escape 不直接丟失；儲存失敗可回到草稿；重新辨識失敗／取消後原已確認資料不變；新舊欄位可選擇，價格與位置不被覆寫。

### UX-03／P1：盒照放大核對

- Editor 圖片可開啟大圖檢視器，提供放大、縮小、重設／適合畫面與關閉；放大後可拖曳移動。
- 桌面支援滑鼠操作，手機支援觸控拖曳；按鈕縮放必須可用，不以雙指縮放作為唯一操作。
- 圖片顯示以現有保存影像為限，不承諾補回壓縮前解析度。
- 檢視器有名稱、焦點管理及鍵盤關閉；Escape 只關閉最上層檢視器，不連帶關閉 Editor，關閉後焦點回到開圖控制項。
- 驗收：桌面和 390px 手機寬度能查看盒面細節，圖片不超出可操作區域；縮放不影響草稿。

### UX-04／P1：位置自動完成與批次設定

- 存放位置建議來自未刪除紀錄的非空位置，去除頭尾空白後精確去重，最近使用者優先；允許自由輸入，不自動合併不同名稱。
- 清單增加多選與「選取目前結果」。列本身已有 button，重構成合法結構，避免 checkbox／button 巢狀互動。
- 批次操作支援設定位置、清空位置及設定系列；「不變更」與「清空」必須分開選項。
- 顯示本次選取筆數及變更預覽。篩選改變時清除選取並提示，避免修改看不見的資料。
- 修改位置保留原 confirmed；修改系列／商品線則設為待確認。每筆沿用規格相容性驗證；有不相容資料時整批不套用，列出原因，不默默改規格。
- 驗收：選 5 筆設定位置只影響這 5 筆；清空位置有效；含 HG／MG 的批次改 HGUC 能指出不相容項目；重開頁面仍保留結果。

### UX-05／P2：篩選與排序

- 保留搜尋名稱、系列、位置、規格；新增系列選單、位置選單（含未填寫）與確認狀態篩選。
- 新增新增時間新到舊／舊到新、名稱、價格高到低／低到高排序；預設新增時間新到舊。
- 空價格不視為 0，兩個價格排序方向都將空值放最後；同值以 createdAt 和 id 保持穩定順序，非法日期採固定退路。
- 以單一查詢函式產生 visible，供清單、連續確認與匯出共用；側欄系列與選單共用同一篩選狀態，不產生互斥但不可見的條件。
- 顯示可逐一清除的條件標籤及「清除全部」；空結果提供復原入口。
- 驗收：混合系列、位置、價格空白及 0 的資料排序正確；查詢不修改原 records 陣列。

### UX-06／P2：匯出範圍預覽

- 點匯出開啟選項：「全部已確認」「目前篩選結果中的已確認」。存在篩選時預選目前結果，無篩選時預選全部。
- 顯示實際可匯出筆數、未確認而排除的筆數與系列分頁摘要；0 筆時禁用該範圍的匯出並顯示原因。
- 預覽建立資料快照，下載使用相同快照，避免 OCR 完成或其他更新造成預覽與下載筆數不同。
- 範圍選擇在 App／查詢層處理；makeWorkbook 仍保留 confirmed 防線，並排除 deletedAt 紀錄。
- 驗收：兩系列含已確認與待確認資料，分別回讀兩種範圍的 Excel，確認筆數、分頁、四欄、價格 0／空白與排序。

### UX-07／P2：手機查找與可讀性

- 小螢幕卡片直接顯示存放位置，未填寫顯示「位置未填」；價格可作次要資訊，不再一起被 value-cell 規則隱藏。
- 作品系列篩選在手機有可見入口，沿用 UX-05，不能只依賴被隱藏的側欄。
- 收藏名稱、位置及表單主要文字建議至少 14px，輔助說明至少 12px；主要觸控控制項以 44px 高度為目標。
- 降低已建立收藏後的大型匯入區占用：可折疊為「新增照片」，辨識進行時仍顯示進度與停止入口。
- 驗收：390×844 與 360×800 無整頁水平捲動；可搜尋、選系列、看位置、編輯和確認，鍵盤焦點可見且固定底部操作不遮擋欄位。

### UX-08／P2：刪除復原與回收桶

- 採軟刪除 deletedAt，刪除後顯示「復原」，並提供回收桶入口；復原提示消失後仍可從回收桶救回。
- 一般清單、統計、位置建議、連續確認、匯出皆排除刪除項目；JSON 完整備份保留回收桶及其狀態。
- 回收桶可復原或永久刪除；永久刪除明確顯示紀錄名稱／筆數並要求確認，本期不做自動到期清空。
- 匯入同雜湊且位於回收桶的圖片時，提示可復原既有紀錄，不靜默跳過。
- 驗收：刪除後刷新仍能復原，價格、照片、確認狀態完整；刪除紀錄不進 Excel；永久刪除後不會再次出現。

### UX-09／P2：備份狀態、遷移與還原預覽

資料契約：

- 既有紀錄 ID 保持穩定；新增 updatedAt、deletedAt（未刪除為 null），編輯／確認／批次／刪除／復原均更新 updatedAt。
- 舊資料缺少 updatedAt 時使用有效 createdAt，否則使用遷移時刻；遷移不得每次載入重新產生 ID 或時間。
- JSON v2 格式包含 version: 2、exportedAt、records；完整保留確認、商品線、OCR 提醒／證據及刪除狀態，但所有輸入仍需型別、長度、圖片、價格與 validRecord 驗證。
- 應用 metadata 保存最後觸發備份下載時間及內容修訂基準，用以計算之後新增／變更筆數（同筆多次修改只計一次）。metadata 不混入收藏陣列。備份與內容基準需對應同一份資料快照。
- UI 用「上次下載備份」描述；瀏覽器無法確認使用者是否真正保存下載，不能聲稱「備份已安全保存」。建議預設 7 天未備份且有變更時顯示可關閉提醒，另顯示尚未備份的狀態。

還原流程：

1. 讀取、驗證與產生預覽，不立即寫入；保留現有 200 MB 上限。
2. 顯示備份版本、筆數、新增／相同／衝突／無效筆數。無效內容阻止套用並顯示可理解原因，不部分靜默還原。
3. 提供「還原完整備份」與「作為外部資料匯入」。完整還原可保留有效 v2 confirmed；外部匯入一律待確認。這是使用者選擇，不靠檔名推定來源可信。
4. 同 ID 且內容相同者略過；同 ID 不同內容列為衝突，預設保留現有，可逐筆採用備份。不同 ID 但相同非空照片 hash 也列為重複／衝突，不無條件覆蓋。
5. 無 hash 的手動紀錄依穩定 ID 去重，不依名稱自動合併（同款多盒可能都是合法資料）。對重複 ID 或同批衝突需明確驗證。
6. v1 備份保留其有效原 ID 供去重；缺少／無效 ID 建立可重複識別的匯入映射或確定性來源識別，保證同檔重匯不一直新增。v1 一律待確認，預覽解釋原因；不要聲稱能判斷不同舊備份中無 ID 無照片紀錄是否同一件。
7. 使用者確認預覽後合併，永不預設清空現有收藏；含刪除狀態的衝突也須預覽。持久化成功才顯示完成，失敗保留原狀並可重試。

遷移安全：先保存舊資料原樣備援，成功寫入並驗證新格式後才切換讀取來源；保留失敗退路，禁止先清空舊 key。對資料與 metadata 需原子更新的操作使用 IndexedDB transaction 或單一一致性 envelope，不以多次獨立 set 假裝原子性。

驗收：v1 與 v2 fixture、手動紀錄、已確認／待確認、回收桶、同 ID 衝突、同 hash 不同 ID、損壞資料、重複還原、容量失敗均有測試。v2 重複還原不增加筆數；有效已確認狀態依模式保留；遷移失敗後舊資料仍可讀。

### UX-10／P2：逐張匯入結果與重試

- 每批建立工作項目：檔名、狀態、recordId（若已建立）、錯誤類別與可採取動作。狀態區分等待、辨識中、成功、重複、格式不支援、檔案過大、解碼失敗、辨識失敗及已取消。
- 顯示處理 n／m、目前階段及各類結果。辨識百分比只代表當前辨識階段，不冒稱整批完成度或不可靠 ETA。
- 維持「完成此張後停止」語意；未開始項目標為已取消，不能算失敗。完成報告分開「已建立紀錄」與「辨識成功」，避免失敗紀錄又算成功。
- 可重試辨識失敗項目，更新原 recordId，不重新新增或被相同 hash 去重擋住。格式／大小錯誤提示先轉檔／縮小後重新選取。
- 頁面重開後，可從保留影像的錯誤紀錄重試；未保存的 File 不宣稱可跨刷新恢復，不需為報告持久保存原始大檔。
- 驗收：一批混入合法、重複、超大、不支援、失敗圖片，逐張原因及總數一致；重試不新增重複紀錄；停止與重新整理中斷都有明確狀態。

## 5. 共用實作品質要求

- 現有 commit 與 useEffect 儲存是分離的。需要「保存成功才前進」的流程，應建立可 await 的一致儲存入口，避免同時保留兩條寫入路徑而重複寫入／競態。
- 所有資料更新由同一入口處理，避免批次匯入、編輯、還原、回收桶彼此覆寫。辨識期間明確禁用會衝突的動作，或以紀錄版本檢查拒絕舊結果覆蓋新修改。
- Dialog 使用一致的焦點限制、關閉與焦點返回機制；巢狀大圖／未儲存提示只讓最上層接收 Escape。
- 保留現有使用者資料，功能狀態、可見清單、匯出、備份使用相同資料契約。
- 不自動發布 Release、不推送遠端；此方案交付的是本機實作與驗證，發布另依使用者指示。

## 6. 測試與驗收方式

每階段先執行適用的純邏輯測試，再建置。涉及互動的階段新增或更新 Playwright 流程；資料遷移與覆寫保護必須有自動測試。使用獨立瀏覽器 context 及測試資料，不操作使用者真實收藏。

```powershell
npm test
npm run build
npm start
# 另一個終端機（已安裝 Edge）
node scripts/check-ui.mjs
```

- 啟動前確認 4173 目前服務來源；不得誤用舊 dist 驗證新碼，也不要終止不明程序。
- 更新既有 check-ui.mjs 以配合匯出預覽、未儲存提示與還原預覽，保留原本真實 OCR／Excel 回讀／離線要求。
- 建議新增純邏輯測試：collection-query、backup-migration、restore-merge；UI 測試涵蓋確認佇列、草稿保護、照片檢視、批次設定及手機操作。
- 可用可控 OCR stub 測試錯誤分支，但不能代替原有真實 sample.jpg OCR 回歸。
